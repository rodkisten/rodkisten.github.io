Built as infrastructure.

RodStorage is intentionally more than a wrapper around JSON.stringify. Its public surface stays stable while storage details, browser capabilities and userscript environments change underneath it.

BACKENDS

IndexedDB first

Automatic fallback to GM storage, localStorage and memory. You can also pin a preferred backend and explicit fallback order.

SCHEMA

Versioned migrations

Sequential migration steps with namespace snapshot rollback when a migration throws.

DATA

Structured serializer

Dates, Maps, Sets, RegExp, BigInt, ArrayBuffer, typed arrays, URL, Error, NaN and infinities survive round trips.

LIFECYCLE

TTL + cleanup

Expiry lives beside each record, with lazy expiration on read and explicit or interval-based cleanup.

CONCURRENCY

Atomic updates + locks

Per-key updates and named locks use Web Locks when present with an in-process fallback.

UI

Reactive stores

get, set, patch, update, reset, subscribe and select make persistent settings usable directly by menus and controls.

SYNC

Cross-tab events

BroadcastChannel invalidates caches and forwards storage events across tabs and same-origin contexts.

PIPELINE

Transforms

Attach global or per-store read/write transforms for compression, encryption, normalization or custom encodings.

OPS

Diagnostics

Inspect backend, schema version, cache hits, estimated bytes, quota, migrations and run a live write/read/delete healthcheck.

API reference.

The entire public API is promise-friendly, even when the chosen backend is synchronous. This keeps application code independent from persistence mechanics.

Quick start

Create one instance per logical namespace, await readiness once, and use it everywhere.

const storage = RodStorage.create({
  namespace: "aio-downloader",
  version: 1,
  backend: "auto",
  sync: true,
  cache: { enabled: true, maxEntries: 500 },
});

await storage.ready();
await storage.set("settings", { debug: true });
const settings = await storage.get("settings");

Typed schema

Pass your storage shape as the generic parameter. Keys and values remain coupled through TypeScript.

interface AppStorage {
  settings: {
    debug: boolean;
    theme: "auto" | "light" | "dark";
  };
  history: Array<{ id: string; url: string; createdAt: number }>;
  metadata: Map<string, { caption: string }>;
}

const storage = RodStorage.create<AppStorage>({
  namespace: "media-tools",
});

await storage.set("settings", { debug: false, theme: "auto" });
// storage.set("settings", { banana: true }) // TypeScript error

Backend selection

auto tries IndexedDB → GM → localStorage → memory. You can choose a backend or control the fallback chain.

const storage = RodStorage.create({
  namespace: "app",
  backend: "indexeddb",
});
const storage = RodStorage.create({
  namespace: "app",
  backend: {
    preferred: "gm",
    fallbacks: ["indexeddb", "localstorage", "memory"],
  },
});
GM supports both modern GM.* methods and legacy GM_* functions when available globally.

CRUD + atomic update

The simple API is enough for most keys. update/atomic serialize modifications per key.

await storage.set("settings", { debug: false, theme: "auto" });
const value = await storage.get("settings");
const exists = await storage.has("settings");
const keys = await storage.keys();

await storage.update("settings", current => ({
  ...current!,
  debug: !current!.debug,
}));

await storage.delete("settings");
await storage.clear();

Reactive stores

Stores wrap one key with defaults, validation, TTL, transforms and subscriptions.

const settings = storage.store("settings", {
  default: { debug: false, theme: "auto" },
  validate(value): value is AppStorage["settings"] {
    return !!value && typeof value === "object" && "debug" in value;
  },
});

await settings.get();
await settings.set({ debug: true, theme: "dark" });
await settings.patch({ theme: "light" });
await settings.update(v => ({ ...v, debug: !v.debug }));
await settings.reset();

const stop = settings.subscribe(value => render(value), true);

const stopDebug = settings.select(
  value => value.debug,
  debug => updateDebugBadge(debug),
  { immediate: true },
);

TTL and cleanup

TTL can be milliseconds or a compact duration. Expired values disappear on read and can be garbage-collected proactively.

await storage.set("metadata", cache, { ttl: "24h" });
await storage.set("temporary", value, { ttl: 15_000 });

const removed = await storage.cleanup();

const storage = RodStorage.create({
  namespace: "cache",
  cleanupIntervalMs: 5 * 60_000,
});

Sequential migrations

Version N runs after N−1. A failed migration restores a namespace snapshot and preserves the previous schema version.

const storage = RodStorage.create<AppStorage>({
  namespace: "app",
  version: 4,
  migrations: {
    2: async ctx => {
      const old = await ctx.get("settings");
      if (old) await ctx.set("settings", { ...old, theme: "auto" });
    },
    3: async ctx => {
      const history = await ctx.get("history");
      if (history) await ctx.set("history", history.slice(-2000));
    },
    4: async ctx => {
      // final v4 shape
    },
  },
});

Transform pipeline

Transforms run after serialization on write and in reverse order before deserialization on read.

const xorTransform = {
  name: "demo-xor",
  write(value) {
    return encrypt(JSON.stringify(value));
  },
  read(value) {
    return JSON.parse(decrypt(String(value)));
  },
};

const storage = RodStorage.create({
  namespace: "private-data",
  transforms: [xorTransform],
});

const auth = storage.store("auth", {
  transforms: [anotherTransform],
});

// Built-ins
const secure = RodStorage.create({
  namespace: "secure-cache",
  transforms: [
    RodStorage.transforms.compression("gzip"),
    RodStorage.transforms.encryption({ key: "your-passphrase" }),
  ],
});
Built-in compression uses CompressionStream. Encryption uses PBKDF2 + AES-GCM via Web Crypto. Key management remains application-specific.

Subscriptions + cross-tab sync

Listen to one key or every change. Remote BroadcastChannel messages are marked with source: "external".

const stopSettings = storage.subscribe("settings", event => {
  console.log(event.operation, event.value, event.source);
});

const stopAll = storage.subscribe("*", event => {
  console.log(event.key, event.operation);
});

stopSettings();
stopAll();

Transactions, atomic updates and locks

Use named locks for multi-step workflows. transaction snapshots the namespace and rolls it back if the callback throws.

await storage.atomic("counter", value => (value ?? 0) + 1);

await storage.lock("media-delivery", async () => {
  await deliverMedia();
  await storage.set("lastDelivery", Date.now());
});

await storage.transaction(async () => {
  await storage.set("foo", foo);
  await storage.set("bar", bar);
  // throw -> namespace snapshot is restored
});

Child namespaces

Build isolated storage trees without inventing key prefixes in application code.

const root = RodStorage.create({ namespace: "rod-devtools" });
const consoleStorage = root.namespace("console");
const networkStorage = root.namespace("network");

await consoleStorage.set("settings", consoleSettings);
await networkStorage.set("history", requests);

Import / export

Exports contain a format marker, namespace, schema version and decoded records. Imports support merge, overwrite and skip-existing strategies.

const backup = await storage.export();
const json = JSON.stringify(backup, null, 2);

await storage.import(backup, { strategy: "merge" });
await storage.import(backup, { strategy: "overwrite" });
await storage.import(backup, { strategy: "skip-existing" });

Typed errors

Use the exported error classes for precise handling and UI feedback.

const {
  StorageError,
  StorageUnavailableError,
  StorageQuotaError,
  StorageSerializationError,
  StorageMigrationError,
  StorageValidationError,
  StorageTransactionError,
} = RodStorage.errors;

try {
  await storage.set("history", hugePayload);
} catch (error) {
  if (error instanceof StorageQuotaError) {
    showQuotaWarning();
  }
}

Single-file TypeScript IIFE

rod-storage.ts is self-contained: no imports, no package runtime and no bundler requirement. Compile it directly with TypeScript.

tsc rod-storage.ts \
  --target ES2022 \
  --lib ES2022,DOM \
  --strict \
  --module none \
  --outFile rod-storage.js
The generated rod-storage.js immediately publishes window.RodStorage. You can still run it through Rolldown/esbuild if your repository already has a build pipeline, but it is not required.

Userscript integration

The source is already a single TypeScript IIFE with no runtime imports. Compile that one file to JavaScript, host it, and load the generated IIFE with @require. It publishes itself on globalThis/window.

// ==UserScript==
// @name         My Userscript
// @match        https://*/*
// @require      https://example.com/rod-storage.js
// @grant        GM.getValue
// @grant        GM.setValue
// @grant        GM.deleteValue
// @grant        GM.listValues
// ==/UserScript==

(async () => {
  const storage = RodStorage.create({
    namespace: "my-userscript",
    backend: "auto",
  });

  await storage.ready();
})();
